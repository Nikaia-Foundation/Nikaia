A programming language · pre-alpha

Write it like a script.
Catch what can be proven at compile time.

Nikaia reads like a scripting language and compiles to Rust. You state a rule with assert, and a call that breaks it does not build. It is fast as lightning, without unsafe. There is no async/await and no garbage collector, and data races are refused at compile time.

Good wins.

Contracts

An assert is a contract.

There is no separate specification language. You write assert(whole > 0) at the top of percent, and it becomes a precondition: each caller has to show that whole is positive.

share only passes its total on, so the duty passes on with it. The call with 0 two functions up is refused, and the error names the value and the assert it came from.

An assert about the value a function returns is a postcondition. at_least_zero never returns less than 0, so per_row knows that r is at least 1 and its call to percent needs no check.

A call whose arguments are all known is run while the program is built. So assert(fib(10) == 54) does not build: fib(10) is 55.

How a claim becomes a contract →

fn percent(part: int, whole: int) -> int {
    assert(whole > 0)
    return part * 100 / whole
}

fn share(done: int, total: int) -> int {
    return percent(done, total)     // hands the duty on to its caller
}

fn at_least_zero(n: int) -> int {
    return 0 if n < 0
    assert(n >= 0)                  // a claim about the result
    return n
}

fn per_row(rows: int) -> int {
    let r = at_least_zero(rows) + 1
    return percent(50, r)           // r >= 1: proved, no check
}

fn main() {
    println(f"{per_row(4)}% {share(3, 4)}%")
    // and this call breaks it:
    println(f"{share(1, 0)}%")
}

Loops

A loop needs no invariant.

The assert after the loop in steps reads total, which the loop changes. Usually a proof tool wants you to write what holds on every turn. Here nobody did.

The compiler looks for such a fact itself, then checks it three times: it holds before the first turn, each turn keeps it, and when the loop ends it gives the claim. --asserts prints the fact it found and how it found it.

In price, p is followed through each assignment and both sides of the if. Every claim here is proved, so none of them costs anything when the program runs.

How a loop is proved →

fn steps(n: int) -> int {
    assert(n >= 0)
    let mut i = 0
    let mut total = 0
    while i < n {
        i = i + 1
        total = total + 2
    }
    assert(total == 2 * n)          // no invariant written
    return total
}

fn price(base: int, member: bool) -> int {
    assert(base >= 10)
    let mut p = base
    if member {
        p = p - 5
    } else {
        p = p + 1
    }
    assert(p >= 5)                  // followed through both branches
    return p
}

fn main() {
    println(f"{steps(5)} {price(12, true)}")
}

The report

Ask what was proved.

nikaia build --asserts lists every assert and what became of it. Proved means no check is left in the program. A precondition is each caller's to show; here every call shows it.

Checked at run time means the prover could not read the claim. It reads sums, differences and comparisons, not the product of two names like w * h. Such a claim does not stop the build. The program checks it when it runs, and the report says why. 

fn average(total: int, count: int) -> int {
    assert(count > 0)
    return total / count
}

fn area(w: int, h: int) -> int {
    assert(w >= 0 && h >= 0)
    let a = w * h
    assert(a >= 0)
    return a
}

fn main() {
    let scores = [3, 5, 9]
    let n = scores.len()
    assert(n == 3)
    println(f"{average(17, n)} {area(4, 5)}")
}

The command line

main's parameters are its command line.

a is a word the program needs. times comes after the ;, so it is named: on the command line it is the option --times, and 4 where it is left out.

The words a program is started with come from outside, so an assert about them cannot be proved. It is checked once the words are read, before the body runs. A wrong word ends the program with exit status 2 and a line that says what is wrong. --help lists the precondition next to the parameter.

How main reads its words →

/// Divides 100 by a, a few times.
fn main(a: int; times: int = 4) {
    assert(a > 0)
    for i in 0..<times {
        println(f"{i}: {100 / a}")
    }
}

Data from outside

A guard, not an assert.

What another program prints is not up to your program. If it is not what you expected, that is not a bug in your code. It is a case your code has to handle.

So an assert about such data is refused, and the error says what to write instead. After an if that handles the bad case, the same assert is proved. 

use std::process

fn main() throws {
    let out = process::run("git", ["rev-parse", "HEAD"])
    let n: int = out.stdout.len()
    assert(n == 41)
    println(f"commit {out.stdout.trim()}")
}

Reading two files at once

Reading a file pauses the function without blocking the program, and you write it as an ordinary call. To run things at the same time, put them in an overlap block. It runs its lines together and waits for all of them.

Whether this runs on one core or on all of them is one line in nikaia.toml. The code does not change.

The whole language on one page →

use std::fs

fn size_of(path: String) -> int throws {
    let text = fs::read_to_string(path, fs::Root::Anywhere)
    return text.len()
}

fn main() throws {
    let (a, b) = overlap {
        size_of("a.txt")
        size_of("b.txt")
    }
    println(f"{a + b} characters in both files")
}

Where Nikaia fits

Easy languages

Python, JavaScript

Quick to write in. The programs are slower and need more memory, and some mistakes only show up in production, under load, at night.

Fast languages

C++, Rust

Fast programs. In exchange, much of each program tells the compiler how memory, waiting and sharing should work.

Nikaia

compiles to Rust

A compiler that sees the whole program can work much of that out itself. You write plain code, Nikaia translates it to Rust, and Rust's compiler checks memory safety.

What that looks like

No async or await

Code that reads files or talks to the network looks like any other code. A call that waits pauses its function, and the program goes on with other work.

Mistakes refused at compile time

Two tasks changing the same data at once is refused, and so is an unchecked value that may be missing or an error nobody handles. The message says what to write instead.

No garbage collector, no free

Memory and files are released at a point you can see in the code, without collector pauses.

One core or all of them

Whether your code may run on several cores is one line in nikaia.toml. The source stays the same.

Formats are part of the language

To parse a log, a protocol or a small language, describe the format as a grammar and the compiler builds the parser.

Readable errors

An error says what you wrote, why it cannot work and what to write instead, with the lines it is about underlined. See one below.

Error messages

The compiler points at every place the explanation needs: ^ under the line with the mistake, - under the line that explains it. Then it says what to write instead.

Errors point at your .nika line and do not talk about lifetimes or borrowing. When no line of yours explains an error, the message says so.

The rules every message follows →

Pre-alpha

The compiler builds real programs today: a calculator, a JSON parser, a log analyser, a small HTTP server, the One Billion Row Challenge. There is no package registry, formatter or language server yet. The roadmap lists what works, the walls you will hit, and where a bug report helps most.
