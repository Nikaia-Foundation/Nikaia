A programming language · pre-alpha

Safe. Fast. Easy to read.
A programming language for software you can rely on.

Nikaia is a programming language for applications: backends, web services, and software that has to be fast and correct at the same time. That is its home.

It also reaches from small scripts down to the hardware, though those areas are still young and come with rough edges.

Nikaia is built around an ambitious goal: safety, performance, and readability without having to trade one for another.

Many bugs follow patterns. Nikaia checks for those patterns before they reach your users, and says where it cannot.

Refused when built

Conflicting actions

Two tasks change the same value at once. One update overwrites the other.

task::scope fn(s) {
    s.spawn fn { balance = balance + 50 }
    s.spawn fn { balance = balance - 30 }
}
error: You're changing `balance` in a task of `task::scope`, and the scope's tasks all share `balance`.
Read more → Partly checked

Tasks that get stuck

Tasks wait for each other forever, or one holds up everyone.

a.update fn(mut acc) {
    acc.balance -= 30
    time::sleep(5.millis())
}
error: `time::sleep` can pause, but you're holding a lock here.
Read more → Specified, not built yet

One task cannot take all your memory

A runaway task cannot crash your whole program. Every task gets a memory budget of its own, as in Erlang and Elixir.

Decided and specified, not built yet: today a task can still take memory from the whole program.

Broken promises

A part of the program is called outside what it was told to expect.

fn percent(n: int) -> int {
    assert(n >= 0 && n <= 100)
    return n
}

percent(140)
error: This call breaks `percent`'s precondition `n >= 0 && n <= 100` every time it is reached.

One core or all of them

Whether your code may run on several cores is one line. The code does not change.

[build]
user-parallelism = "no"    # or "yes"
Read more → By design

No garbage collector, no free

Memory is released at a point you can see in the code, without collector pauses.

You write no free and no lifetimes. The compiler works out when memory can be released, and the release is a point you can see.

Checks that are proved are dropped

An index or overflow check that cannot fail is not written, where you ask for it.

[build]
optimization = "remove-bounds-checks:on,remove-overflow-checks:on"

Readable errors

An error says what you wrote, why it cannot work and what to write instead.

error[NK1139]: You're changing `count`, but it wasn't declared as mutable.
help: Add `mut` where it's declared: `let mut count`.
Read more → A grammar, not a parser

Formats are part of the language

Describe a format as a grammar and the compiler builds the parser.

grammar Calc {
    entry rule expr -> i64 =
        head:term tail:add_tail* { … }

    rule add_tail -> i64 =
          "+" t:term { t }
        | "-" t:term { -t }
}

Why Nikaia exists

Good and fast are not opposites. Nikaia is named for Nika, and nik means good.

“Good wins.” Not over anyone: it denies that good and fast are opposites, and that being decent to the person writing the code has to be paid for at runtime.

Where Nikaia fits

Easy languages

Python, JavaScript

Quick to write in. The programs are slower and need more memory, and some mistakes only show up in production, under load, at night.

Fast languages

C++, Rust

Fast programs. In exchange, much of each program tells the compiler how memory, waiting and sharing should work.

Nikaia

fast and safe

A compiler that sees the whole program can work much of that out itself. You write plain code and Nikaia turns it into optimised machine code. Nikaia checks your program, and Rust's compiler checks memory safety again.
