Very fast

Against tuned Rust

The problem
Fast languages usually ask you to spell out how memory, waiting and sharing should work. Plain code should not cost you speed.
An example
The One Billion Row Challenge: read a very large file of measurements and aggregate them. The Rust side is a tuned entry that maps the file, skips UTF-8 validation and hashes a word at a time, with unsafe. The Nikaia side describes the file as a grammar.
What Nikaia checks
Both are release builds on one core with the same output. Counted in instructions per row, not in seconds: Nikaia needs 300 where tuned Rust needs 272, with UTF-8 and every overflow checked, and about half the mispredicted branches. The Nikaia source is shorter and has no unsafe.
The limit
This is one program on one workload. It shows what the compiler can do for that program, not that every program is this fast. The method and the current tables are in the repository, and the numbers there are the ones to quote.
