Very safe

Broken promises

The problem
Every part of a program should be able to rely on what the other parts promise.
An example
A function expects a percentage between 0 and 100 but is called with 140.
What Nikaia checks
You write the expectation as an assert and it becomes a contract. A call that breaks it is rejected when the program is built, a promise about a result is available to the callers, and a contract carries across package boundaries.
The limit
A compiler cannot know whether data from files, arguments or the network is valid. Check it where it enters the program; once checked, the rest of the code can rely on it.
Show the program and what Nikaia says 
fn percent(n: int) -> int {
    assert(n >= 0 && n <= 100)
    return n
}

fn main() {
    println(f"{percent(140)}")
}

$ nikaia check main.nika

For data from outside, check it where it arrives. After the guard, the claim is proved:

let out = process::run("git", ["rev-parse", "HEAD"])
let n: int = out.stdout.len()

Contracts

An assert is a contract.

There is no separate specification language. You write assert(whole > 0) at the top of percent, and it becomes a precondition: each caller has to show that whole is positive.

share only passes its total on, so the duty passes on with it. The call with 0 two functions up is refused, and the error names the value and the assert it came from.

An assert about the value a function returns is a postcondition. at_least_zero never returns less than 0, so per_row knows that r is at least 1 and its call to percent needs no check.

A call whose arguments are all known is run while the program is built. So assert(fib(10) == 54) does not build: fib(10) is 55.

How a claim becomes a contract →

fn percent(part: int, whole: int) -> int {
    assert(whole > 0)
    return part * 100 / whole
}

fn share(done: int, total: int) -> int {
    return percent(done, total)     // hands the duty on to its caller
}

fn at_least_zero(n: int) -> int {
    return 0 if n < 0
    assert(n >= 0)                  // a claim about the result
    return n
}

fn per_row(rows: int) -> int {
    let r = at_least_zero(rows) + 1
    return percent(50, r)           // r >= 1: proved, no check
}

fn main() {
    println(f"{per_row(4)}% {share(3, 4)}%")
    // and this call breaks it:
    println(f"{share(1, 0)}%")
}

Loops

A loop needs no invariant.

The assert after the loop in steps reads total, which the loop changes. Usually a proof tool wants you to write what holds on every turn. Here nobody did.

The compiler looks for such a fact itself, then checks it three times: it holds before the first turn, each turn keeps it, and when the loop ends it gives the claim. --asserts prints the fact it found and how it found it.

In price, p is followed through each assignment and both sides of the if. Every claim here is proved, so none of them costs anything when the program runs.

How a loop is proved →

fn steps(n: int) -> int {
    assert(n >= 0)
    let mut i = 0
    let mut total = 0
    while i < n {
        i = i + 1
        total = total + 2
    }
    assert(total == 2 * n)          // no invariant written
    return total
}

fn price(base: int, member: bool) -> int {
    assert(base >= 10)
    let mut p = base
    if member {
        p = p - 5
    } else {
        p = p + 1
    }
    assert(p >= 5)                  // followed through both branches
    return p
}

fn main() {
    println(f"{steps(5)} {price(12, true)}")
}
