# ADR-401: `thread::id()` Names the Calling Thread with a Number

**Status:** Accepted
**Date:** November 18, 2026
**Answers:** how a test sees that two calls ran on the same thread, which
"Unobservable std tests" (#2088) found no way to say in Nikaia for the
library's kept threads (ADR-284 D9)
**Related:** [ADR-284](adr-284.md) D9 (a library's `_async` calls run on kept
threads); [ADR-400](adr-400.md) (`std::mem` counts per thread; a type that
allows only `==` was refused there)

## 1. Question

```nika
// a C program calls the library's `work_async` twice, one after the other
pub fn work() -> int {
    // did the second call run on the thread the first one used?
}
```

`std`'s Rust test compares `std::thread::current().id()` of the two calls. A
Nikaia program has no way to name the thread it runs on.

## 2. Options

| Option | Why it lost | See |
| :--- | :--- | :--- |
| Infer it from `mem::allocations()` (a kept thread's count keeps growing, a new one starts near zero) | it reads one thing to learn another; a test that says "same thread" should say it | D1 |
| An opaque thread type that allows only `==`, as Rust's `ThreadId` and C++'s `std::thread::id` | a type with no other use is foreign to the language (owner, ADR-400) | D1 |
| No thread name at all, as Go refuses a goroutine id | Go refuses it to keep programs from goroutine-local state; Nikaia has no thread-local state to key, and the id names an OS thread, not a task | D2 |

## 3. Decision

### D1 — `thread::id()` is the calling thread's number.

`std::thread::id() -> int` is a number for the thread that calls it, as
Java's `Thread.threadId()`, Python's `threading.get_ident()` and C#'s
`Environment.CurrentManagedThreadId` give one. Two calls on the same thread
give the same number; two threads alive at once never share one.

```nika
let first = thread::id()
// ...
assert thread::id() == first
```

### D2 — The number names a thread, not a task, and is never reused.

A task may be resumed on another thread than the one it began on; `id()`
names the thread at the moment of the call. Numbers are handed out in
increasing order from 1 for the life of the process and never reused (as
Java's), so a thread started after another one ended never looks like it.
The number is not the operating system's thread id and not an address.

### D3 — `std::thread` holds nothing else.

Concurrency stays with tasks (Part II); `std::thread` gains no way to start,
join or name a thread.

## 4. Reasons

* **Common.** Java, Python, C#, Rust and C++ all let a program name its
  thread; the ones with a number are the plainest to compare and print.
* **Says what the test means.** "The same thread" is checked as equal
  numbers.
* **Leaks nothing.** A counter, not an OS id or an address.

## 5. Consequences

* **Part I** gains the module `std::thread` with `id()`.
* **What it costs.** One per-thread number taken from a process-wide counter
  on first use, the function, tests.
* **What it risks.** A program that keys state by thread number breaks when
  a task moves threads; D2 says so.
