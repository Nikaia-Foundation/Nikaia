# ADR-403: A Package's Test Programs See Its Private Names

**Status:** Accepted
**Date:** November 18, 2026
**Answers:** how a test reaches a pure function that is not public API, which
"Child environment assembly in Nikaia, Windows case tested directly" (#2119)
and the abort `lookup` move (#2120) found missing (#2130), and which a test of
a compiler pass entry met the same way (#1983); decided by the owner
(2026-11-18)
**Related:** [ADR-269](adr-269.md) D22 (a test program is `tests/NAME.nika`
and `use`s the package as an integration test does) and its `test` block,
which already sees private names; [ADR-243](adr-243.md) D6 (a deciding
condition passed in, as `found_on_path` takes the platform)

## 1. Question

The owner's pattern for a branch no program reaches (2026-11-18): the branch
becomes a pure Nikaia function with the deciding condition as an input, and a
Nikaia test calls it directly. Such a function is not API:

```nika
// crates/nikaia-std/src/runtime/abort.nika  (package `runtime`, within std)
fn lookup(table: ref Vec[(int, String, int)], generated: int) -> (String, int)? { ... }
```

```nika
// crates/nikaia-std/src/runtime/tests/an_unknown_line_is_not_guessed_at.nika
use runtime

fn main() {
    let table = [(10, "main.nika", 3), (20, "main.nika", 7), (30, "lib.nika", 1)]
    println(runtime::lookup(table, 20))   // NK1171 today: no such function
    println(runtime::lookup(table, 11))
}
```

Today the test sees only what is `pub` (ADR-269 D22), and for std's runtime
that means an entry with `pub = true` in `std.contracts`, which would make
`lookup` a promise to every program. Rust's unit tests, Go's `_test.go` in the
same package, Java's package-private and Zig's `test` blocks give the tests of
a module what the module sees; Kotlin's `internal`, C#'s
`InternalsVisibleTo` and Swift's `@testable import` widen the view for named
test code. Nikaia already does the first for a `test` block.

## 2. Decisions

### D1 - A program in a package's `tests/` sees what the package sees.

`tests/NAME.nika` of a package that `use`s the package reaches its names that
are not `pub` - functions, types, fields, methods - by the same paths as its
public ones, as a `test` block in the package's own files does (ADR-269). This
changes D22's "as an integration test does": the program is still its own
program, built and run as D22 says, and its `.stdout`, `.stderr` and `.stops`
are judged the same way.

### D2 - Nothing else does.

Another package, a program outside the package's `tests/`, an example and a
`tests/` program of a package that depends on this one see only `pub` names,
as before. That a test reaches a name publishes nothing: no contract enters
the ledger for it, no `std.contracts` entry is needed, and the name may change
without a version raise.

### D3 - std's packages are packages for this.

A part of std written in Nikaia with its own manifest (`runtime`, `compiler`,
`within = "std"`) has a `tests/` directory under D1. `nikaia test` runs it,
and the full suite runs it with the rest. A program in std's
`tests/compiler/tests/` is not inside those packages and sees std's public API
only.

### D4 - The package is built for its own tests as its own crate, with every item `pub`.

A `tests/` program is its own Rust crate and the package another
([ADR-286](adr-286.md) D19), and the package's private items are emitted
without `pub`, so rustc refuses what D1 allows (found by the build of this
ADR, #2141). The package a `tests/` program of its own links is therefore
lowered from its source for that program with every item `pub`: a build of
its own, with that choice in its cache key, linked by the package's own
`tests/` programs and by nothing else. The package's ordinary build is
unchanged and stays private, so rustc remains the one enforcer ADR-286 D2-D3
keep: no second build sees the widened one.

For std's packages (D3) it is the same rule: a program in `runtime/tests/` or
`compiler/tests/` links the package lowered from its `.nika` for it, with
every item `pub`, and `nikaia-std` for the rest of std. The `nikaia-std`
crate gains no `pub` item for it (#2142). If a package's lowered code cannot
stand as its own crate (it names `crate::` parts of `nikaia-std`), that is a
defect of the lowering met by this build, fixed there.

## 3. Consequences

* The pure functions the owner's pattern writes - `merged` and `same_name`
  (#2119), `lookup` (#2120) - are tested directly with no new public std API.
* A compiler pass entry can be called by a test in
  `crates/nikaia-std/src/compiler/tests/` (#1983).
* A `tests/` program can depend on a private name: a refactor of the package
  changes its own tests, which is where that cost belongs.

## 4. What this does not decide

* A way for Rust code's private items to be reached from Nikaia; the owner
  named it as the fallback where the pattern is not enough, and nobody has
  needed it yet.
* A `tests/` program of one std package reaching another's private names
  (`compiler` tests calling into `runtime`): D2 refuses it; a case that needs
  it is a new question.
