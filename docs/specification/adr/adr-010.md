# ADR-010: Input Provenance — Trust Is a Property of Sources

**Status:** Accepted
**Resolves:** the default hasher, left open by [ADR-296](adr-296.md)
**Related:** [ADR-283](adr-283.md) (the edges trust travels along),
[ADR-005](adr-005.md) D3 and D8 (the ledger and its determinism),
[ADR-017](adr-017.md) (the second consumer, decided separately per D8),
[ADR-316](adr-316.md) (the function within a class),
[ADR-037](adr-037.md) D7-D8 (the same question for a reference count)

## 1. Context

The threat is hash flooding: an adversary who chooses keys can drive an
open-addressed table into quadratic behaviour.

The axis is **provenance** — where the keys came from — and not how the program
is built. A
single-threaded server hashing attacker-supplied header names is exactly as
vulnerable as a parallel one, and a compute job over an operator-chosen file has
no adversary in either. Provenance is a property of the *input*, known where the
input enters the program, and it is the user's call at that point rather than a
global default the language picks for them.

Rust's standard map hashes everything with a DoS-resistant function because Rust
has no whole-program provenance information; with nothing to distinguish the two
cases, assuming the worst everywhere is the only safe global default, and every
compute workload pays for it. Nikaia already ties every view to the buffer it
points into ([ADR-283](adr-283.md)) and already solves whole-program contracts,
so it can be exact instead of pessimistic — and pay for hardening only where an
adversary exists.

## 2. Decisions

### D1 — Trust is a two-state lattice over sources.

`Trusted ⊑ Untrusted`. Every buffer entering the program carries one state,
derived values inherit it, and a container's state is the **join** of what goes
into it — so a map that receives one untrusted key is untrusted. Which maps
count as one container is D9's.

This rides machinery that exists. The trust bit travels the same edges
[ADR-283](adr-283.md) already records, lands in the same ledger, and is solved by
the same monotone fixpoint, so [ADR-005](adr-005.md) D8's determinism, ban list
and CI cover it unchanged. A two-element lattice adds no solver and no new pass.

**Barriers widen to `Untrusted`** — a `dyn` boundary, an FFI value, a Rust
dependency's return. This is the opposite direction from
[ADR-283](adr-283.md) D5's representation barrier, deliberately: there the
conservative answer is the wider representation, here it is the safer one. **An
analysis that fails open is a vulnerability generator.**

### D2 — The standard library classifies its own sources.

Users do not classify `std`. The library states, per source, who supplied the
bytes:

| Source | Default | Why |
| :--- | :--- | :--- |
| `http` request line, headers, query, body; `net` sockets; IPC; WASM host imports | **Untrusted** | a remote peer chose these bytes |
| `fs` reads and maps, `cli::args`, `env`, compile-time data | **Trusted** | the operator chose these bytes |
| `db` result rows | **Untrusted** | second-order: a row may hold what a user stored earlier |

The database row is why "trusted = local" would be too crude: stored data is
attacker-chosen data with a delay. Any source whose content can be influenced by
someone other than the operator is untrusted, whatever transport it arrives on.

### D3 — The user states the requirement at the source, in both directions.

```nika
// A service processing files uploaded by strangers. Local path, hostile bytes.
let data = fs::map(path; trusted: false)

// A benchmark harness reading a fixture it wrote itself.
let body = socket.read_all(; trusted: true)
```

The default is a default, not a verdict, and the decision belongs where the data
enters. Both forms use the existing named-parameter convention and both are
recorded in the ledger with their source location — which makes the security
review of a Nikaia program a grep over one generated file, diffable across
commits, rather than an audit of every call site.

The same marker is available on a function parameter, so a library can state
what it assumes rather than inheriting the join of its callers.

### D4 — A grammar may declare a floor.

```nika
@untrusted
grammar HttpHeaders { … }
```

A grammar *is* the specification of an input format, and its author often knows
the threat model better than the person applying it. Effective trust is
`join(grammar floor, buffer trust)`, so a grammar marked `@untrusted` cannot be
used in trusting mode by accident, whatever buffer it is pointed at.

There is deliberately no `@trusted` floor: a format cannot make its input safe.

### D5 — What the compiler does with it: choose the hasher, and nothing else.

| Effective trust | Hash |
| :--- | :--- |
| `Trusted` | fast non-cryptographic hash, fixed seed |
| `Untrusted` | keyed hash, per-process random seed |

Everything else about the map is identical: same table, same absence of
per-entry allocation, same API, and the same full-content equality
([ADR-283](adr-283.md) D11, [ADR-296](adr-296.md) D14). **Trust never weakens a
correctness property; it selects the class of hash function.**

Within a class, the function follows the keys' shape, and a program may name
its own hasher where it makes the map.
*Changed by [ADR-316](adr-316.md) D1 and D4.*

How the program is built enters only as an implementation detail of *how*, never
as the thing that decides *whether*. When and for which maps together the
choice is made is D9's.

**The random seed must be real.** On a target with no entropy source the build
fails rather than falling back to a fixed seed: a keyed hash with a predictable
key is the vulnerability wearing the mitigation's clothes.

### D6 — Map iteration order is unspecified and may vary between runs.

Randomised seeding means an untrusted map iterates differently from run to run.
Stated in the spec rather than discovered; a program that needs an order asks
for one. The compiler's own ledger paths are already forbidden from iterating
hash order at all ([ADR-005](adr-005.md) D8), so the rule the language enforces
on itself is the rule it teaches.

### D7 — The choice is visible, never a mystery.

`--trust` (on `build`, `run`, `test` and `lower`, [ADR-260](adr-260.md) D3)
prints the provenance of every buffer and the hasher
chosen for every map. Where a hardened map sits in a hot loop, a lint names the
source that made it untrusted — so "why is this slower than I expected" is one
command, and the fix is in the message.

### D8 — Build the mechanism; decide only the hasher here.

Provenance is a taint lattice and hashing is its consumer. It is built as a
mechanism rather than a hasher special case so that a further consumer — SQL
parameterisation, log injection — can be decided on its own. **A path is not
one**: where a name reaches the filesystem it names its root at the call
([ADR-108](adr-108.md)), and no provenance travels a path.

One caution belongs on the record now, and is settled by
[ADR-017](adr-017.md): escaping at a template hole must stay
**unconditional**, defence in depth. A provenance analysis that silently skips
escaping on "trusted" data turns one wrong `trusted: true` into an XSS hole.
Provenance may add evidence and lints there; it may not switch escaping off.

### D9 — A map's hasher is decided once the whole package is read, for every map that must be one type; at the package's boundary it is a type parameter each use fills in.

*Added October 11, 2026 (#581).*

```nika
// stock.nika
pub struct Tally { pub counts: collections::HashMap[String, i64] }

pub fn count_in(mut t: Tally, word: ref String) {
    t.counts[word.clone()] = 1
}

// main.nika, the same package
let mut t = Tally { counts: collections::HashMap() }
count_in(t, line)        // `line` from a file: fast; from a socket: keyed
```

D5's choice is a choice of type in the code the compiler writes: the fast map
and the keyed map are two types there, and every place that names a map has to
name the same one as the value it receives. So the choice is made for **classes**
and at **one time**:

1. **Positions and classes.** Every place a map type is written is a
   position: a field, an enum's payload, a parameter, a result, a `let`, a map
   inside another type (`Vec[HashMap[K, V]]`, `HashMap[K, V]?`). Positions a map
   value passes between - initialised from, assigned, passed, returned, stored,
   compared with `==`, the arms of one `if` or `match` - are one **class**, and
   a class is one type.
2. **One time: after the package.** A class is keyed where any key that reaches
   any value of it is untrusted, or where it holds a position D1 calls a
   barrier; otherwise it is fast. The answer is taken after every file of the
   package has been read and every call in it resolved against all of them. It
   is a union of positions and a join over a two-element lattice, so neither
   the order the files are read in nor which file builds or fills a map can
   change it ([ADR-005](adr-005.md) D8). Inside the package, a position of a
   declaration that is not `pub` has its class's type, the same at every use.
3. **At the boundary, a type parameter.** A map position in a `pub` type is a
   hidden type parameter of that type, one per position, in the order the
   declaration writes them. A map position in the signature of a `pub` function
   or method is one of that item's, **one per group of positions its body makes
   one map** (a map assigned to another, compared with `==`, returned from a
   parameter): a body that joins none gives each position a parameter of its
   own. Each use fills them, in the package and outside it, as a use of a
   generic fills its type: from the class the value it hands in or takes out
   belongs to. A map the item's own body makes at such a position is made with
   the hasher the parameter holds.
4. **The ledger says what the body puts in.** A `pub` function's entry gets
   `maps`, one line for each group of positions: the positions it joins
   (`t.counts` is a map field of a parameter, `<result>` the result) and what
   its body adds to them: `from(p, ...)` keys as trusted as the arguments
   named, `from()` none (nothing that is not the caller's choice), `keyed`
   keys it does not trust, or a barrier. A caller joins the line into its own
   classes. A position no line covers is keyed. The key is read as a
   permission, as `sync` is: a wrong `from(..)` would let a caller choose the
   fast hash for keys an adversary picked, so only the compiler writes it, and
   only where the body is read to its end: a map handed to a call, kept in a
   local, matched or captured makes every line of the function `keyed`, and
   then the positions of one written type are one group.
5. **Barriers fix a position keyed:** a method of a trait (its implementations
   may sit in packages this build never reads, and a call through `dyn` has one
   compiled body), a described Rust crate's signature (its type is the one the
   crate wrote, and std's map is keyed), and a binding for another language
   ([ADR-284](adr-284.md) D26). A class holding one of them is keyed.
   A `pub` function or method that hands a map it was given to a barrier, or
   to a private function that has a map of its own in its signature, has that
   position fixed keyed: a hidden parameter cannot be shown to be std's hasher
   or the class of a private declaration. A method that hands a map of `self`
   on does so for its type: the `impl`'s parameters are the type's, so the type
   declares none and its maps are the keyed map, and a program that builds it
   is no more trusted than that. The type a grammar rule returns, and the
   accumulator of its fold, are written with the hasher the package fills
   every other mention with.
6. **The names Rust code sees** are `nikaia_std::hash::Fast` and
   `nikaia_std::hash::Keyed`. A `pub` type's map parameters default to `Keyed`,
   so Rust code that names `Tally` gets the map that is safe for any key, and
   names `Tally<Fast>` where it vouches for its keys, as any Rust code that
   picks a hasher does.
7. **A conflict is not possible by join** - keyed wins, which is D1's safe
   direction - and none is resolved by a conversion: a copy into a new map
   makes no key more trusted. A class can only be fixed to two things by a
   hasher the program names ([ADR-316](adr-316.md) D4): two different ones in
   one class, or one in a class a barrier fixes to another, is refused,
   `NK1246`.
8. **`--trust` reports classes** (D7): for each, the positions in it, the type
   it got, and the key or barrier that made it keyed.

**Why this shape.**

* **"All the information" is the package.** A package is checked against its
  dependencies' ledgers and never against its callers, which a library build
  does not have. A choice that waited for the whole program would give one
  library two meanings for two programs, and could not be written into the
  ledger the package ships.
* **The class, not the declaration.** The type has to agree wherever a value
  passes, so a declaration is fixed together with every declaration its values
  pass through. That is the cost: one untrusted use slows every private map its
  values share a position with. Following each map only inside its function
  would cost more: every map that leaves one would have to be keyed.
* **A type parameter at the boundary, because a package reaches its consumer
  as source.** Its lowering is compiled together with the program that uses it,
  so a hidden parameter is monomorphised there and costs no run-time branch. A
  fixed choice at the boundary would make every library's maps keyed, which is
  the global default §4 rejects for compute workloads, or fast, which hands
  attacker keys to a fixed seed.
* **Rust sees a type that does not move.** The parameters follow from the
  declaration alone; a file elsewhere in the package that starts reading a
  socket changes which argument a use passes, never the type's shape. An
  untranslated backend error cannot come from it (Part III C.1).
* **The hasher stays out of the source** ([ADR-316](adr-316.md) §4): nothing a
  program writes mentions the parameter.

**Rejected:**

* **The choice per file, or the entry file's for every file.** Per file, a
  field's type and the expression that fills it disagree wherever two files of
  one package come out differently; the entry file's answer for all of them
  gives a socket's keys the fast hash wherever the entry file reads nothing.
* **One map type with the hasher chosen at run time** (an enum seed in every
  map). The type would never move, but every hash pays a branch and every fast
  map carries a key it does not use; [ADR-316](adr-316.md)'s measurements show
  1BRC's row cost moving with three branches. And the choice is the compiler's
  to make while it builds.
* **The keyed hash at every public position**, as [ADR-037](adr-037.md) D8 puts
  the atomic count there. D8's reason, that a published artifact has already
  chosen its representation, does not hold for a package lowered and compiled
  with its consumer. Whether `Shared` should follow is not decided here.
* **The hasher in the written type** (`HashMap[K, V, H]`): rejected in
  [ADR-316](adr-316.md) §4.
* **A rule for the toolchain's own package only** - one package exempt from
  what every other package gets.

## 3. What this makes of two programs

A program that maps a file named on the command line gets a fast hash: the
benchmark does not pay for a threat it does not have, and nobody wrote a line
about hashing. Deployed to crunch uploads from strangers, the change is one
named argument, and the ledger records it.

A server hashing query parameters and header names off a socket is `Untrusted`
by default, hardened without anyone remembering to ask, and the DSL for the wire
format can pin it so no later use can lower it.

Two shapes of program get different code from the same source text, and the
difference is derived from where the bytes came from — not from a build switch,
and not from a global default that is wrong for one of them.

## 4. Rejected alternatives

* **A global default, either one.** Fast-everywhere ships a DoS bug in every
  server written in the language; hardened-everywhere taxes every compute
  workload for an adversary that does not exist. The information needed to
  choose is available, and refusing to use it is the actual mistake.
* **A default that follows the build mode** — answers the wrong question (§1),
  and silently changes a library's security properties when it is built
  differently, which is exactly what [ADR-005](adr-005.md) D8 keeps out of the
  ledger.
* **A hardened constructor the user must remember** — security that depends on
  remembering is the model Nikaia exists to replace. The safe case must be what
  happens when nobody thought about it. Survives as D3's override, where the
  user is thinking about it by construction.
* **Pure inference with no user statement** — the compiler cannot know that a
  local file holds hostile uploads, or that a socket is a trusted internal peer.
  Inference sets the default; the user sets the truth.
* **Adaptive hashing** (start fast, detect pathological collisions, rehash) —
  deferred, not rejected. Attractive because it needs no provenance at all, but
  it makes worst-case latency data-dependent. Revisit if the keyed hash is ever
  measured to be a real server's bottleneck.

## 5. Risks

* **A wrong `trusted: true` is a silent vulnerability.** Mitigated by barriers
  failing safe (D1), `std` owning the classification so common cases need no
  judgement (D2), every override landing in one auditable file (D3), and a DSL
  author being able to pin the floor beyond a user's reach (D4).
* **This defends against hash flooding only.** Quadratic parsing, backtracking,
  unbounded allocation from a length field are untouched. Bounded repetition
  ([ADR-296](adr-296.md) D13) is the adjacent lever; neither is claimed here.
* **Provenance is only as good as the source table.** Adding a `std` source
  without classifying it defaults to `Untrusted`, which is safe but may
  surprise. The table is part of the module's spec, not an implementation note.
