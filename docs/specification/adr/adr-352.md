# ADR-352: `null` Is a Pattern in a `match` Over a `T?`

**Status:** Accepted
**Date:** October 14, 2026
**Answers:** how a `match` takes a `T?` apart (issue #612)
**Related:**
[ADR-279](adr-279.md) (nullable types);
[ADR-291](adr-291.md) (patterns, `else`, guards);
[ADR-350](adr-350.md) (a test that proves a `T?` is not `null`);
Part I 3.4; Part III 17.1

## 1. Question

**Can a `match` name the empty case of a `T?`?** A `T?` is a `T` or nothing
(Part I 2.3). `??`, `?.` and `if x != null` take it apart where one case is
special; where the nothing and several values of the `T` each have their own
answer, the program needs a `match`, and a `match` had no pattern for the
nothing.

## 2. Decisions

### D1 — `null` is a pattern; the other arms match the `T`.

In a `match` over a `T?`, `null` is the arm taken where the value is not set.
Where a `match` has a `null` arm, every other arm is matched against the `T`
inside: a bare name binds the plain `T`, a literal compares with the value
(`0 =>` over an `i64?`), a variant names one of the `T`'s variants, and a
guard works as on any arm (`null if c =>`).

```nika
match count {
    null => "unknown",
    0 => "none",
    n if n > 9 => "many",
    n => f"{n}",
}
```

**Why.** The principle of ADR-350: where the compiler has proved the value is
set, it is a `T`. An arm after the nothing has been given its own arm meets
only values, so the name it binds is a value and needs no `??`.

### D2 — A `null` arm and a catch-all are a complete `match`.

Over a `T?` with a `null` arm, the nothing is covered by an unguarded `null`
arm or by `else`, and the rest is counted against the `T` as any `match` over
a `T` is: an unguarded bare name covers it, an enum's variants are counted,
`true` and `false` cover a `bool`. A guarded `null` arm covers nothing, as no
guarded arm does (ADR-291 D11). What is missing is `NK1151`.

**Why.** The same rule as every other `match`, with one case added to it: no
second notion of completeness.

### D3 — `null` over a value that is never `null` is refused (`NK1256`).

A `null` arm in a `match` over a type that is not a `T?` can never be taken,
and is refused rather than ignored. Where the subject's type is not known,
nothing is claimed.

**Why.** An arm that cannot run is a misreading of the type, and it would
also change what the other arms bind.

### D4 — Lowered to `None` and `Some(…)`.

`null` is `None`; every other arm but `else` is `Some(<pattern>)`.

## 3. Rejected

**B: nullables stay out of `match`**, taken apart only with `??`, `?.` and
`if`. Where three or more cases meet - nothing, a special value, the rest -
it nests an `if` around a `match` over `x ?? <a value that cannot occur>`,
whose fallback is dead code that reads as if it mattered (ADR-350 A).
