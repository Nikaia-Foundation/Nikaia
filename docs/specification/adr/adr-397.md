# ADR-397: The Environment Is Untrusted Unless Marked `trusted: true`

**Status:** Accepted
**Date:** November 14, 2026
**Answers:** who chose the bytes of an environment variable, which
[ADR-010](adr-010.md) D2 answered *the operator* and [ADR-365](adr-365.md)
left open; whether an `assert` about one is checked or refused; what a value
from the environment may reach
**Related:** [ADR-010](adr-010.md) D2, D3, D5, D8 (the sources, the marker at
the source, the hasher, the further consumers); [ADR-365](adr-365.md) (standard
input and files); [ADR-396](adr-396.md) (`NK1302`); [ADR-108](adr-108.md) (a
path names its root); [ADR-243](adr-243.md) D5-D8 (a child's environment);
Part III 14.2, 17.1; #1597

## 1. Question

```nika
let depth = text::parse_i64(env::var("DEPTH") ?? "8") ?? 8
assert(depth > 0)
log("user agent: " + (env::var("HTTP_USER_AGENT") ?? ""))
```

ADR-010 D2 took the operator to have chosen the environment, so the `assert`
is a check that stops the program, and the second line writes the text as it
is. The operator is often not who chose it: a CGI host puts a request's
headers into the environment (`HTTP_USER_AGENT`, `QUERY_STRING`), a program
run with more rights than its caller (setuid, `sudo` keeping variables, a
service started by a job runner) inherits what the caller set, and a CI job
sets variables from a pull request. The same bytes through a socket are
untrusted (ADR-010 D2), through standard input or a file as well (ADR-365).

## 2. Options

| Option | Why it lost | See |
| :--- | :--- | :--- |
| Keep it trusted; `trusted: false` at the source | the unsafe answer when the marker is forgotten: an analysis that fails open (ADR-010 D2's own rule, ADR-365's reason) | D1 |
| Untrusted only for names a host is known to fill (`HTTP_*`, `QUERY_STRING`) | a list of names says nothing about who set the others; a caller chooses every variable a child inherits | D1 |

## 3. Decision

### D1 — Every value read from the environment is untrusted.

`env::var` and `env::vars` (#1597) hand back **untrusted** text: an `assert`
about it is `NK1202`, an index it reaches is proved or refused (`NK1302`,
ADR-396), and a map keyed by it gets the keyed hash (ADR-010 D5). The text
keeps that provenance through every value made from it (Part III 17.1).

`env::temp_dir()` and `env::current_exe()` give a path, and no provenance
travels a path (ADR-010 D8): where a path reaches the filesystem it names its
root (ADR-108).

### D2 — `trusted: true` at the source says the operator chose it.

`env::var("DEPTH"; trusted: true)`, `env::vars("APP_"; trusted: true)`: the
text is trusted, an `assert` about it is checked as any claim is, and its maps
may take the fast hash. The marker is recorded in the ledger with its place,
so a review finds every one (ADR-010 D3).

### D3 — Where it goes, it goes as untrusted data does.

A value from the environment is not written raw where untrusted data is not:
into a log, a terminal, a query or a page it goes the way a header or a line
from a socket goes there, escaped where that consumer escapes. The consumers
themselves are ADR-010 D8's, decided once for every untrusted source and not
for the environment alone; log injection is still open there.

## 4. Reasons

* **Fail closed.** A forgotten marker costs a guard or a slower hash, never a
  claim about bytes a stranger chose; the other default costs the reverse.
* **The call does not know who set the variable.** A host, a caller with fewer
  rights, a CI job: the environment is one more way a stranger's bytes reach a
  local program, as standard input and a path are (ADR-365).
* **One rule for outside data.** A consumer that escapes untrusted text
  escapes the environment's with it; no source is a hole in it.

## 5. Consequences

* **Part III 17.1** names the environment untrusted and `trusted: true` its
  marker; ADR-010 D2's table changes with it. Part III 14.2 says so at
  `std::env`.
* **What it costs.** `std`'s provenance for `env::var` and `env::vars`, the
  `trusted:` option on both, `--trust`'s report, tests; programs that read
  their own configuration and make a claim or a map from it write
  `trusted: true`.
* **What it risks.** A program that asserts about its own setting without the
  marker meets `NK1202`; the message names the marker and the guard.

**Not decided here:** `cli::args`, trusted as ADR-010 D2 has it; `main`'s
parameters are checked where they arrive (ADR-360).
