Commit: check: a view unwrapped by ?? or a match stays a view (part of #1107)
Body: Four causes, each fixed where it was. (1) `let c: ref C = m[k] ?? return null` / `m.get(k) ?? ...`: `check_core_stmt_let` asked ADR-354's element-view rule only of a bare place; it now also asks it of an element read past a jump (`check_core_stmt_an_element_past_a_jump`), sharing one rule with `check_core_stmt_element_view` (`check_core_stmt_read_viewed`), as kind 3 (not a lent `let`), because the read past the jump is the reference below already. (2) the `match` binding over a view with a `null` arm took `ref` only for a type that moves (`check_core_flow`, `takes_away`); a struct that copies is lent too (ADR-279 D8). (3) an unannotated `let c = m[k] ?? return null` of a struct that does not copy (already a reference below, `view_of` since #1044) is now typed `ref C`, as `let c = m[k]` is. (4) `return m.get(k)` into `ref C?` is a view (`a_get_off_a_lent_parameter`, by the parameter's type, since lending is asked before the call is typed), with no `&` added. The NK1131 of #1044/#1057 (`an_element_read_handed_back_by_value`, `a_field_of_an_element_read_handed_back`) is kept for such a view: the binding keeps its `view_of` (`viewed_past_a_jump`), `check_core_a_lent_place_given_away` asks `does_not_copy` of what the view views, and a `return` it refuses is not asked again for its type. The only tools lowering that changed is `check_items.rs` (`&generic` -> `generic`, the view now bound). The test's rows 4-5 use a struct that does not copy, see Deviation.
