## Issue #1044 (copied, widened by the architect's probes on the fast binary at adf64938)
Found while building #859 step 4. `let s = path.last() ?? return null` then `return s`, over a `Vec` of a type that does not copy, lowers `s` as `&T` and rustc stops with E0308. The issue's own probe used a described type; a user struct shows it the same way.

```nika
struct Sym { name: String, n: i64 }
fn last_sym(path: Vec[Sym]) -> Sym? {
    let s = path.last() ?? return null
    return s
}
```
Lowered: `fn last_sym(path: &[Sym]) -> Option<Sym> { let s = match path.last() { Some(v) => v, None => return None }; Some(s) }`.

Rows (all probed; every one passes `nikaia check` and fails in rustc today):

* b: the same with `path.first()`.

* d: `return path.last()` directly (no `let`).

* Text is not affected: over `Vec[String]` row a runs (tiering, ADR-282), leave it.

## The rule (decided; no owner question)
Nikaia never copies behind your back. Part I and Part III already say so for both halves: a map's value that does not copy, kept where a `T?` of its own is wanted, "is written `m[k]?.clone()`" (Part I, `10-nikaia-light.md` ~1766-1770); and `NK1131` refuses a piece of a borrowed subject handed back by value, "a `let` over a place" among the borrowed subjects (Part III, `30-nikaia-tooling.md:1746`, the `NK1131 also` sentence). An element read by `first()`, `last()`, `get(i)`, `m[k]` or `m.get(k)` is a view of what the list or map keeps (owned or lent alike), so rows a-f are `NK1131`, with the help `…?.clone()`. **Not** a silent clone; **not** a new code.

## Cause (traced for rows a-c and e-f's `let` shape; row d unverified)
`check_core_a_lent_place_given_away` (`check_core_leaves.nika:74`) refuses a name given away whole only when the local's `view_of` is set (`Expr::Variable` arm, :82-121; `if (local.view_of == "" && !a_let_view) || !keeps { return }`). `view_of` is set in one place only, the `for mut` binding (`check_core_stmt.nika:1646`, `local.view_of = dotted_path(world, iter) ?? ""`). A `let` bound to an element read through `??` with a jump fallback never sets it, so the return passes. Row d (`return path.last()` with no name) is a method call, which the function's `match value` has no arm for: it is the same rule, but the architect did not trace which arm it needs.
