## Issue #1055 (copied; every row probed by the architect on the fast binary at 0329f310)
A `??` with a jump fallback whose left side is an optional field (a type that does not copy) read off **another** `??` result - a list or map element - passes `nikaia check` and lowers to a `match` that moves the field out of the element: rustc refuses it (E0507 cannot move out of a shared reference). With the inner step bound by its own `let`, the same code runs (`match c.signature.as_ref()`).

```nika
use std::collections
struct Sig { name: String }
struct Con { signature: Sig? }
fn first(m: collections::BTreeMap[String, Con], key: String) -> String? {
    let sig = (m.get(key) ?? return null).signature ?? return null
    sig.name.clone()
}
fn main() {
    let mut m: collections::BTreeMap[String, Con] = collections::BTreeMap()
    m.insert("k", Con { signature: Sig { name: "one" } })
    println(first(m, "k") ?? "none")
}
```
Lowered: `let sig = match match m.get(..) { Some(v) => v, None => return None }.signature { Some(v) => v, None => return None };` (want `.signature.as_ref()`).
