## Issue text (#557, copied; decided: ADR-339 D2, Part II 10.8)
* Step 3 (copied): "**`same_line`:** the generated parser records by position what its last `WS` skip held. Tests: `a\n[0]` and `f\n(x)` are not an index and not a call (ADR-307 D4); `a [0]` is."
* ADR-339 D2 (copied): "`same_line` matches nothing and fails where the whitespace skipped just before it held a line break. The generated parser records, by position, what its last `WS` skip held, so the answer is a fact about the input and survives backtracking: a branch that fails has written what a branch that succeeds would have." Part II 10.8's table (`docs/specification/20-nikaia-advance.md` :650): `same_line` binds nothing. ADR-339 D3: no *grammar* declares a state or an `extern rule`; the **lowering** may write both into the generated `grammar!`.

* **Where the generated parser is written:** `emit_grammar.nika` `emit_grammar_over` :196 and `emit_grammar_body` :207 (step 2's template rules `__nikaia_span` / `__nikaia_here` :250-266 are the pattern: a built-in the grammar does not declare itself becomes a template rule, found by `emit_writes_a_built_in` :50). Today the generated `grammar!` writes **no `WS`** where the grammar declares none: `winnow-grammar` skips its default whitespace.
* **Decided (architect):** only a grammar that writes `same_line` (and declares no rule of that name) changes; every other generated grammar stays byte for byte. In such a grammar the lowering writes (a) a `state` of a small record type in `nikaia_std::grammar` (two fields, `end` and `newline`, `ran` and `began_a_line` as `PrTrivia`'s; one type, not a second copy of `PrTrivia`'s comment logic), (b) a `WS` that records the run it skipped: the grammar's own `WS` renamed (e.g. `__nikaia_ws_body`) under a `WS` that binds what it matched `@ at` and records `(at, the bytes hold b'\n')`, or, with no own `WS`, the default whitespace written out the same way, (c) a template rule `__nikaia_same_line` (an `extern rule` over a hand-written function after the block, as :132 is), and (d) the entry functions building the parse input with that state. Over `Bytes` and over text alike (`same_line` needs no `text::Pos`, so it is not refused over text).
* **Decided (architect): a line break anywhere in the skipped run counts, inside a block comment too** (ADR-339 D2's words: "the whitespace skipped ... held a line break"). The Rust `Trivia` counts only breaks outside comments, so `a /*\n*/ [0]` is an index there and not here; the `[` stands on a new line, which is what ADR-307 D4 asks. Write this case into the test and name the difference in `Body:` (step 4 compares the port on every `tests/compiler` program and must know it).
