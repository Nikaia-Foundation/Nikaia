# Brief: #1046, an untyped let lambda handed to a fn parameter that may pause lowers as a plain closure

Score: compiler bug (b1043's Found, row d), false acceptance (`nikaia check` passes, rustc refuses); bugs-first default of `docs/priorities.md`. Small, one cause traced.

## Issue #1046 (copied)
Found by b1043 (row d), probed by the architect on the fast binary after 569bb244. #997 is incomplete for a callee whose `fn` parameter may pause.

## Problem
```nika
fn apply(f: fn(i64) -> i64) -> i64 {
    return f(1)
}
fn main() {
    let add = fn(x) { x + 3 }
    println(f"{apply(add)}")
}
```
Expected `4`. `nikaia check` passes; rustc refuses: "`i64` is not a future" (required by a bound in `apply`). Lowered:
```rust
async fn apply(f: &impl AsyncFn(i64) -> i64) -> i64 { f(1).await }
let add = |x| { x + 3 };
println!("{}", apply(&add).await);
```
Rows:
* a: the program above - rustc refuses.
* b: `let r = apply(add)` then `println(f"{r}")` - same.
* c: `apply(f: fn(i64) -> i64 sync)` - runs, `4` (#997's own test uses `sync` parameters, so it never met this).
* d: `apply(fn(x) { x + 3 })` inline - runs, `4`, lowered `apply(&async |x| { x + 3 })`.
* e: `let add: fn(i64) -> i64 = fn(x) { x + 3 }` - runs (a `Kept`, wrapped at the call).

## Cause (traced)
`check_core_stmt_let` (`check_core_stmt.nika:544-564`) types the lambda by its first use (#997: `lambda_params_by_use`, `run_code`) but does not record that the use may pause. An inline lambda gets that from `check_core_args_lambda` (`check_core_args.nika:101-115`: `future_lambdas`, `run_lambdas` when `!is_sync`), and `emit_arg_future` (`emit_core_args.nika:600`) writes `async |..|`. The let's lambda is emitted by `emit_core_closure` (`emit_core_flow.nika:235-280`), which writes `async ` only for `pausing_lambdas` (std entries, `check_crossings.nika:432`), so it comes out a plain closure.
