Commit: lowering: a fn parameter handed round a call cycle is a &dyn Fn (Part of #1023)
Body: ADR-277 D11 gains its sentence: a run sync code parameter of a function on a cycle of the call graph is written &dyn Fn. emit_reach's code_on_a_cycle builds the graph over the functions that run a sync code parameter (only they carry a lambda's type on; trait-impl methods keep the trait's shape and are left out) and searches from the function being written. A &dyn parameter handed on unlent is lent once more (&&dyn Fn is a sized Fn for an &impl Fn taker and coerces for a &dyn one), also from a lambda inside the function (walk.dyn_code, keyed by walk.keep_function). In tools, 25 recursive walks (bounds, prover, views, comptime_tree, ...) now take &dyn Fn: one indirect call per call of the parameter, the decision's cost.
