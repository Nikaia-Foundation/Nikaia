# Brief: #1036, a tuple result holding a view of an argument made in the call keeps that argument (rustc)

## Issue #1036 (copied)
```nika
fn pair(s: String) -> (String, i64) {
    return (s.trim(), 1)
}
fn main() {
    let p = pair(f" ab{1} ")
    println(f"{p.0}")
    let (k, n) = pair(f" cd{2} ")
    println(f"{k} {n}")
}
```
Expected `ab1`, `cd2 1`. Re-run by the architect on the fast binary of 08:06 (after #999's e064b36e): rustc *temporary value dropped while borrowed* at `gen:113`, twice. Lowered `fn pair(s: &str) -> (&str, i64)`, called `pair(&format!(..))`. With a `String` result the argument goes into a keep (`(&__keep_N).put(format!(..))`, ADR-283 D24); with a named argument the tuple form works.

Traced: `made_arguments` (`crates/nikaia-std/src/tools/buffers.nika:1632`) makes an argument made in the call a source only when the callee's result is a view or a struct of views: `if !result.is_a_view() && !a_struct_of_views(result, ask) { return }` (:1636). A tuple result with a view part is neither, so no `Source::Argument`, no plan entry (`plan.calls` :1993), and `argument_keep` (`emit_keeps.nika:97`, asked at `emit_core_args.nika:468`) finds nothing.
