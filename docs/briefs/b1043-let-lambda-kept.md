# Brief: #1043, a lambda bound by an untyped `let`, handed where a function value is kept, is kept (rustc)

Score: compiler bug, false acceptance (`nikaia check` passes, rustc refuses) on the plainest way to name a function value; bugs-first default of `docs/priorities.md`. Found by b1034b (3571b0bf).

## Issue #1043 (copied)
A lambda bound by an untyped `let` and then handed where a function value is kept (a `fn` parameter the callee keeps, a returned `fn`, a struct field of `fn` type) passes `nikaia check` and reaches rustc as a bare closure where `Kept<dyn Fn ..>` is wanted. With the type written (`let add: fn(i64) -> i64 = fn(x) { x + 3 }`) the same program runs (`4 5`, probed), and an inline lambda in the same place runs too. Part I 5.4: a function value in a result or a field is kept.

Probes, run by the architect on the fast binary of 08:06 (each its own program):
* a) `fn keep(f: fn(i64) -> i64) -> fn(i64) -> i64 { return f }`, `main`: `let add = fn(x) { x + 3 }`, `let t = keep(add)`, `println(f"{t(1)}")`: rustc *Mismatched types* at `let t = keep(add)`, expected `Kept<dyn Fn(i64) -> Pin<Box<dyn Future<Output = i64>>>>`, found closure.
* b) `fn mk(k: i64) -> fn(i64) -> i64 { let g = fn(x) { x + k }; return g }`, `main`: `let t = mk(2)`, `println(f"{t(1)}")`: the same rustc error at `return g`.
* c) `struct H { f: fn(i64) -> i64 }`, `let g = fn(x) { x + 1 }`, `let h = H { f: g }`, `println(f"{h.f(1)}")`: NK2605 at check (`H.f` can fail with `?`); with `H { f: fn(x) { x + 1 } }` it prints `2`. **Unverified** that it shares the cause.

Traced (a, b, by reading the code): `check_core_a_kept_lambda` (`crates/nikaia-std/src/tools/check_core_leaves.nika:211`) marks a closure kept (`facts.kept_lambdas`, result, hulls, captures), and a `Variable` only when it names a function of this program (:241-245, `state.lookup(named) == null && world.own.functions.contains_key(named)`, then `check_core_a_kept_function` :272). A local bound to a run-only lambda falls through both, so the emitter writes the plain closure. A typed let works: `check_core_stmt.nika` hands its closure to `check_core_a_kept_lambda` with the declared type (the assignment at :1245 does the same).

Not this brief: `add(1)` after `keep(add)` (or after `apply(add)`) is NK1245, the type of an untyped lambda's parameter taken from a later call: #833 (`decision`). Do not put such a row in the test. Do not write `fs[0](1)` or `same(inc)(1)` (parser, #1042).
