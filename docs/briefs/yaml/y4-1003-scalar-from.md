## The decision (owner, 2026-10-30, recorded on #1003)

* `scalar::from(n) -> scalar` (`n: i64`; narrower integers widen into it, Part I 2.2) with a **precondition, not an optional result**: `n` is not a surrogate (`0xD800..=0xDFFF`) and not above `0x10FFFF` (and not negative). It is held as any precondition is (ADR-269 D5, D20; ADR-380): proved at a call where the caller's facts prove it; where not proved, refused under `unproved-claims = "error"` (the default, `NK1300`) or checked at run time under `"warn"`; `--asserts` lists it. Write it as a `std` function whose `assert` publishes the precondition in `crates/nikaia-std/std.contracts` (`requires`), the way ADR-269 §5 says `std` carries its own.
* `n as scalar` from any integer type other than `u8` is **refused** by the checker, with a help naming `scalar::from`. Use `NK1241` (an `as` that can lose a value; Part I: "the program says by name what it means"); if it does not fit, ask under `Needs:` for a code, do not invent one. `b as scalar` from a `u8` always fits and stays.
* Today an integer `as scalar` is a run-time checked cast (`FactNarrowing::ToScalar`: `crates/nikaia-std/src/tools/check_reads.nika` ~441, `check_facts.nika` ~54, `emit_core_places.nika` ~489; test `tests/compiler/tests/an_integer_cast_as_scalar_is_checked.nika`), and a literal (`8232 as scalar`) skips that path and reaches rustc (#1003's probe). Both give way to the refusal.
