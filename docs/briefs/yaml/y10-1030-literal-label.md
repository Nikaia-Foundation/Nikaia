## Issue (#1030, copied)

Probe (the architect ran each row below on 94f07e7b):

```nika
grammar G {
	rule WS = "" -> { }
	entry rule top -> String = x:"ab" eof -> { x }
}
fn main() {
	let r = G::top("ab") catch {
		println("error")
		return
	}
	println(r)
}
```

`nikaia check` passes; `nikaia run` fails in rustc, `Mismatched types` at the action (over text and over a let-bound `Bytes` alike; the y9 builder saw `Lifetime may not live long enough` with a temporary `Bytes(..)` argument, which is #1004). The same with `x:text("ab")` prints `ab`. A choice of literals stored in a `String` field, `x:("+" | "-") eof -> { T { s: x } }`, fails the same way. Used inside the action only it works: `n:"-"? ... -> { f"{n ?? "+"}{d}" }` prints `-12`, `+7` (and `examples/1brc.nika:49`).

## Cause (architect)

`CheckState::pattern_type` (`crates/nikaia-std/src/tools/check_grammar.nika:48`) has no `Pattern::Literal` arm, so a literal's label is `Ty::Unknown`; a rule `-> String` whose action returns a `text(..)` capture is lowered as `-> &'a str` (a view of the input, `pattern_text()`), one returning a literal capture keeps `-> String` and its `&str` value does not fit. The emitter already treats a literal's capture as text (`emit_pattern.nika:72`, over bytes wrapped in `text(..)`, ADR-366 D2). `choice_type` (same file) returns `Unknown` when its first alternative is, so the choice shape should follow from the same arm (unverified).

Part II 10.8's table says `"text"` yields nothing; the row for `x:p` says a label binds what `p` yields. What the compiler does (a label on a literal binds the matched text) is the meaning in use (`examples/1brc.nika`); the table row gets that sentence.
