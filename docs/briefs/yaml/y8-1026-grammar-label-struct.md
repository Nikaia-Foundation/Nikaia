# Brief: #1026, a view field read from a struct a grammar label binds stays a view

Score: a compiler defect that blocks #928 step 2b (yaml properties and aliases, `y2c-properties.md`, next in this batch); bugs before moving.

## Issue (#1026, copied)

A rule that returns a struct of views, bound by a label in another rule (`p:P`), hands its fields on as *text of its own*: `p.a` going into the struct the outer rule returns is refused with NK1106, and with it every other alternative that puts a view into the same field. The same read through a function of the program works (#803: `let p = props()` then `Pair { a: p.a, .. }` runs; the architect ran that too). ADR-282 D13: "a function of the program answers with its declared or decided result; a read of an element hands on what the position is", and a grammar's rule is a function of its grammar for this walk (`declare_rules`).

Probe (the architect ran it on 9d92e474):

```nika
struct Props { a: String }
pub struct Pair { pub a: String, pub b: String }

grammar G {
	rule WS = "" -> { }
	rule Word = digit+ -> { }
	entry rule top -> Pair = x:text(Word) " " y:text(Word) eof -> { Pair { a: x, b: y } } | p:P " " y:text(Word) eof -> { Pair { a: p.a, b: y } }
	rule P -> Props = "&" x:text(Word) -> { Props { a: x } }
}

fn main() {
	for t in ["12 34", "&12 34"] {
		let b = Bytes(t.bytes().collect())
		let r = G::top(b) catch {
			println("error")
			continue
		}
		println(r.a)
		println(r.b)
	}
}
```

Today: two NK1106 (`Pair.a holds String, but you're giving it ref String`) at `x` (7:76) and at `p.a` (7:130). Without the second alternative it runs. The y2 builder saw the same with a `String?` field, with `let an = p.a`, and with `match p { Props { a: x } => .. }`. Expected output: `12` `34` `12` `34`, one per line.

## Cause (architect, read on 9d92e474)

`bind_grammar_pattern` (`crates/nikaia-std/src/tools/text_tiers.nika`, `Pattern::Bind` arm, about line 5231) binds a label with `plain_local(kinds)`, so the local's `of` (the struct it holds) stays `null`. A field read finds its position through `tier_struct_of` -> `struct_of_local` -> `local.of` (about lines 2962, 3199); with none, `field_place` is null and `field_kinds` answers `owned_kinds()`, so `Pair.a` sees a view and own text. For a call `called_struct` (about 3022, #803) names the struct; for a loop's binding `walked_struct` (`local.of = walked`, about 2315).
