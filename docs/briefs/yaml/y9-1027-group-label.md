# Brief: #1027, a label on a one-element group binds its value

Score: a compiler defect found by y8 (#1026); bugs before moving. Nothing in `yaml` waits for it (the y2 draft labels rules directly), so it is small and first.

## Issue (#1027, copied)


Found by the y8 builder (#1026, 2026-10-31). Part II 10.8: `( p )` is grouping and yields *as `p`*; `x:p` binds what `p` yields. So `n:(P)` binds what `P` yields. Today `nikaia check` passes and rustc refuses the emitted grammar: `Cannot find value 'n' in this scope`. `n:(P | Q)` (two alternatives) and `m:(P)?` work; `n:(P)`, `k:((P))`, `s:(text(digit+))` do not.

Probe (the architect ran it on 7f6b8151):

```nika
struct N { v: i64 }
grammar G {
	rule WS = "" -> { }
	entry rule top -> i64 = n:(P) eof -> { n.v } | "?" m:(P)? eof -> { (m ?? N { v: 9 }).v } | "(" k:((P)) eof -> { k.v } | "t" s:(text(digit+)) eof -> { s.len() as i64 }
	rule P -> N = "&" -> { N { v: 1 } }
}
fn main() {
	for t in ["&", "?", "?&", "(&", "t123", "x"] {
		let r = G::top(Bytes(t.bytes().collect())) catch {
			println("error")
			continue
		}
		println(r)
	}
}
```

Today: three `Cannot find value` (`n`, `k`, `s`). Expected (the same program with the parentheses removed prints it): `1` `9` `1` `1` `3` `error`, one per line.

## Cause (architect)

The emitter writes the group as written (`n:(P)`, `emit_pattern.nika`, `Pattern::Group` arm, line 104). The backend, `winnow-grammar` (rev 3b2dd3d, a pinned git dependency this repository cannot change), reads a one-alternative group with a label as a scope of its own: the name stays inside. A group around one element means nothing beyond that element (10.8: "as `p`"), so the emitter writes the element without the parentheses when the group holds one element that is neither a sequence nor a choice, nested groups included (`((P))` is `P`). A group around a sequence or a choice keeps its parentheses.
