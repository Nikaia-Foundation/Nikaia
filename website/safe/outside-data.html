Very safe

Data from outside

The problem
What another program prints, what a request carries or what a person types is not up to your program. When it is not what the code expected, that is not a bug in the code but a case the program has to handle.
An example
A program asks git for the current commit and assumes the answer is 41 characters long. In a directory that is not a repository, the answer is an error message instead.
What Nikaia checks
The compiler knows which values come from outside the program. A claim about such a value, an assert or a function's precondition, is refused until a guard handles the bad case where the data arrives; after that line the claim is proved, and the rest of the program can rely on it. Words on the command line are checked against main's preconditions before the body runs. A path from outside is opened under a directory the call names, and a name that leaves it, such as ../../etc/passwd, is stopped at the call. A map whose keys come from the network gets a hash with a random seed, so whoever sends the keys cannot choose ones that collide.
The limit
The compiler cannot know what valid data is for your program; the guard says that, and the compiler checks that there is one. Where the program vouches for a source itself, with fs::Root::Anywhere or trusted: true, the compiler takes its word, and nikaia build --trust lists every such place. Today a file read while the program runs still counts as trusted, although the specification counts it as outside data.
Show the program and what Nikaia says 
use std::process

fn main() throws {
    let out = process::run("git", ["rev-parse", "HEAD"])
    let n: int = out.stdout.len()
    assert(n == 41)
    println(f"commit {out.stdout.trim()}")
}

$ nikaia build
error[NK1202]: `n == 41` is a claim about data from outside the program.
  --> …/outa/src/main.nika:6:5
   |
 6 |     assert(n == 41)
   |     ^^^^^^^^^^^^^^^
   |
   = note: `n` comes from outside the program, so nothing the compiler can see says what it holds.
   = note: That it is wrong is a case the program has to handle, not a defect an `assert` catches.
   = help: Check it where it arrives, with a guard the program handles: `throw BadInput(n) if !(n == 41)`, or `return … if !(n == 41)`. After that line, this `assert` is proved.

After an if that handles the bad case, the same assert is proved:

use std::process

fn main() throws {
    let out = process::run("git", ["rev-parse", "HEAD"])
    let n: int = out.stdout.len()
    if n != 41 {
        println("not a commit id")
        return
    }
    assert(n == 41)
    println(f"commit {out.stdout.trim()}")
}

A name from outside is opened under the directory the call names. The second name leaves it, and the call refuses it:

use std::fs

fn main() {
    for name in ["a.txt", "../../etc/passwd"] {
        let text = fs::read_to_string(name, fs::Root::Dir("store")) catch {
            println(f"refused {name}: {error}")
            continue
        }
        println(f"{name}: {text.len()} bytes")
    }
}

$ nikaia run main.nika
a.txt: 3 bytes
refused ../../etc/passwd: the name leaves the root it was given: ../../etc/passwd
