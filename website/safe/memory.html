Safe, secure, reliable

A memory budget for every task

The problem
A single runaway task can use up all the memory and bring down the whole program, including the parts that were working fine. Nikaia keeps such a task from taking the rest of the program down with it.
An example
A background task reads a large upload into memory, and keeps reading. Your main application, which was serving requests, runs out of memory with it.
What Nikaia checks
Every task gets a memory block of its own, and a list the task builds and keeps to itself is placed in it. A task that fills its block ends with task::OverBudget, an error like any other. Only that task ends. The tasks beside it run on, and the function that started it hands the error to its caller, which handles it or fails with it. A task that places nothing in its block cannot end this way, so nobody is asked to handle it. A shared value is to get a budget of its own too, which is specified and not built yet. A calculation that runs while the program is built is already bounded in steps and in memory.
The limit
The block is a fixed 64 KiB for now, and its size is not yet chosen to fit the machine. Only the lists a task keeps to itself are counted, so text and values a task hands on still come from the whole program, and main runs outside every block. A task waited for with join reports a full block as task::Crashed, which tells it with over_budget(). The budget is a protection while the program runs, not a proof. Nikaia does not show at build time that a task stays within its budget, but it makes sure that a task which does not ends with task::OverBudget, an error like any other, and only that task ends. Memory that a Rust crate or a C library allocates and keeps for itself is in no budget.
