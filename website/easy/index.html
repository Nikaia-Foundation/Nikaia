Plain calls

Waiting does not split your code in two

A function that waits does not have to be marked as one, and so it does not mark its callers either. Code does not split into a waiting half and a non-waiting half, and no library needs two versions of the same function, one for each. The program waits where it needs the value.

A call that reads a file or waits for the network is written like any other call. Its function pauses there until the result is ready, and the program goes on with other work in the meantime. The compiler finds where a function pauses, so a function that starts to wait leaves its callers as they are. A function marked sync does not pause; the compiler holds it to that, and it may call only other sync functions.

To run things beside each other, a program puts async before an expression: it starts at once, and the program waits for the value where it is first needed. A task’s error is thrown at that point, and an async { … } group ends only when every task in it has ended. Handles, detached tasks and tasks whose calls pause are specified and still being built (#988).

let a = async count_words(first)    // starts at once
let b = async count_words(second)   // runs beside the first
println("both counts have started")
println(f"{a + b} words")           // waits for both

Says what to write

Readable errors

A compiler message that talks about lifetimes and borrowing sends you away from your own code.

What Nikaia checks. The compiler points at every place the explanation needs: ^ under the line with the mistake, - under the line that explains it. Then it says what to write instead. Errors point at your .nika line and do not talk about lifetimes or borrowing.

The limit. When no line of yours explains an error, the message says so. Where a check passes a problem on to the Rust compiler underneath, the error it raises is reported against your .nika line.

error[NK1139]: You're changing `count`, but it wasn't declared as mutable.
help: Add `mut` where it's declared: `let mut count`.

Grammar in, parser out

Formats are part of the language

Reading a log, a protocol or a small language usually means a parsing library, or a parser written by hand.

What Nikaia checks. You describe the format as a grammar, and the compiler builds the parser. Precedence and recursion are rules: the order of the rules is the order of binding. The whole calculator is about 100 lines.

The limit. A grammar is a large topic, and this page shows only the idea. The full rules are in Part II, chapter 10.

grammar Calc {
    entry rule expr -> i64 =
        head:term tail:add_tail* { … }

    rule add_tail -> i64 =
          "+" t:term { t }
        | "-" t:term { -t }
}
