Easy to understand

Waiting does not split your code in two

Running two things at once

Lines run in the order they are written. To run work beside the code after it, a program writes async before an expression. async e starts e at once, and the program waits for its value where the value is first needed. In the program below both counts run while the first println does its work, and a + b waits for both. It compiles with today’s compiler and prints both counts have started, then caught: 5 words is too long and 0 words.

struct TooLong { words: int }
impl Error for TooLong {
    fn message(self) -> String {
        return f"{self.words} words is too long"
    }
}

fn short_count(text: String) -> int throws {
    let n = text.split(" ").count()
    if n > 4 {
        throw TooLong { words: n }
    }
    return n
}

fn total(first: String, second: String) -> int throws {
    let a = async short_count(first)     // starts at once
    let b = async short_count(second)    // runs beside the first
    println("both counts have started")
    return a + b                         // waits for both; an error is thrown here
}

fn main() throws {
    let n = total("the quick brown fox", "jumps over the lazy dog") catch {
        println(f"caught: {error}")
        0
    }
    println(f"{n} words")
}

A task’s error is thrown where the program waits for the task, and the compiler asks for it to be handled there, as for any call that can fail: here total says throws and main catches it. In the same way f(async g(), async h()) runs g and h beside each other and calls f when both are done, and f receives plain values, so its signature does not change. Written as a statement, async e starts a task without a value, and async { … } is a group that ends only when every task started in it has ended, also when the function leaves it early with a return. A failure nobody reads is thrown at the end of its group. Older programs use overlap and spawn, which the compiler still accepts; async replaces both.

A call that waits is an ordinary call

A function that waits for a file or the network is written like any other function, and a call to it like any other call, because the compiler finds where a function pauses. A call that waits pauses its function, and the program goes on with other work. A function that starts to wait leaves its callers as they are. Where a piece of code must not wait, the function says sync; the compiler holds it to that, and it may call only other sync functions.

Built, and still being built

Built today: a task whose call pauses, such as reading a file or waiting for the network; a task to be joined or cancelled later, started with async(handle); one that may outlive the function that started it, started with async(detached), a task being cancelled only through such a handle; and within:, a deadline on a task or on a wait (A deadline for every wait). With user_parallelism: yes the tasks of a group run on every core.

Still being built (#986, #987, #988): async(deferred), a task that starts only when asked to; the options limit: and admission:, which bound how many tasks run at once and when the next one starts; lambdas of xs.par_iter() that pause; and a panic in a task that ends only that task, where today it still ends the program.

What the compiler checks about tasks

An async whose value is needed in the very next line is refused, because nothing runs beside it, and the message suggests removing the word. A jump such as return out of a task is refused, and so is a group that starts no task. A task that changes a name bound outside it is refused, and so are two tasks that write the same file, the same lock or standard output, naming what they share (Two tasks changing the same value); where the compiler cannot tell what a call touches, it does not refuse. Each task is to get a memory budget of its own, so that a task that uses it up ends with task::OverBudget and the rest of the program runs on; that is specified and not built yet, and memory a Rust crate or a C library allocates for itself is not counted (A memory budget for every task).
