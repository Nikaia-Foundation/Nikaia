Easy to understand

No async, no await

The problem
In many languages, code that waits has to be marked everywhere it touches: async here, await there.
An example
Read two files and add up their sizes. Reading a file waits for the disk.
What Nikaia checks
Any function can run asynchronously without you writing it: a call that waits pauses its function, and the program goes on with other work. You write it as an ordinary call. There is no async/await colouring, so a function that waits never forces its callers to change. That is decided and stable.
The limit
Every function may pause unless it says otherwise. A function marked sync never pauses and may call only other sync functions, which is how you say that a piece of code must not wait.
Still open
How tasks are orchestrated is being worked out: the exact forms are being examined: today's overlap and par_iter, and forms like thread::scope and par. Under discussion are let async and other forms, aiming for a syntax that is familiar, safe and expressive, and so more uniform. The example below uses today's overlap.
Reading two files at once 
use std::fs

fn size_of(path: String) -> int throws {
    let text = fs::read_to_string(path, fs::Root::Anywhere)
    return text.len()
}

fn main() throws {
    let (a, b) = overlap {
        size_of("a.txt")
        size_of("b.txt")
    }
    println(f"{a + b} characters in both files")
}
