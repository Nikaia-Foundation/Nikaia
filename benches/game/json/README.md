# The json package against serde_json

Reading and writing JSON, which almost every server does: the
[json package](../../../packages/json) against `serde_json`, the library a Rust
program uses (#1620, part of the Benchmarks Game table, #1611).
`nikaia run benches/game/game.nika -- json` builds both sides, checks that they
print the same bytes and counts them with callgrind.

## The programs

| level | Nikaia | Rust |
|---|---|---|
| the tree | [`tree/src/main.nika`](tree/src/main.nika): `json::parse` into a `json::Value`, written back with `json::to_string` | [`rust-tree.rs`](rust-tree.rs): `serde_json::Value`, written back with `serde_json::to_string` |
| a type of the program | not built yet: the package's way is `json::read[T]` (ADR-344 D3, ADR-grammar-typed-read-v2 D10), which waits for its build (#604) | `#[derive(Deserialize)]`, with it |

serde_json is built with `preserve_order` (an object keeps its members in the
order of the text, as `json::Value` does), `arbitrary_precision` (a number is
kept as the text it was written as, as `json::Value` keeps it) and
`unbounded_depth` (serde_json stops at 128 levels unless told otherwise; the
package reads 512). Both sides then write back the same text byte for byte:
members in order, numbers as written, no blanks, the escapes RFC 8259 asks for.

## The inputs

Generated by [`input.nika`](input.nika), so every machine counts the same bytes
and no data file is kept here:

| input | bytes | what |
|---|---:|---|

| large | 10,000,080 | records as above, and every tenth line 200 coordinate pairs as canada.json holds them |

## Where json was behind

When it was first counted (Nikaia 0.0.1403, serde_json 1.0.149), json
counted 1.4 to 2.0 times serde_json's instructions. From
`callgrind_annotate` of the large input, checks off (2.46 billion against
serde_json's 1.37 billion):

* **The path of every value was built while reading** (30 %; 42 % on deep):
  `value` made `f"{path}[{at}]"` and `f"{path}.{key}"` for each element and
  member, text only an error ever shows. Since *json builds a value's path
  only when reading fails* it is built only then.
* **Text was copied a character at a time** (24 %): `parse` first collected
  the whole input into a list of characters (`text.chars().collect()`, 6 %),
  and a number or string was then built by pushing one character after
  another (`Text::push`, about 30 instructions a call on its own). Since
  *json reads the input's bytes in place and cuts numbers and strings from
  it* it reads the bytes in place.

Now json counts fewer instructions than serde_json on the large and deep
inputs and 1.20 times as many on the small one, whose count is mostly the
start of the process. Those 1.20 have not been attributed yet.
