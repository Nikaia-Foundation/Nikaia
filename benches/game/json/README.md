# The json package against serde_json

Reading and writing JSON, which almost every server does: the
[json package](../../../packages/json) against `serde_json`, the library a Rust
program uses (#1620, part of the Benchmarks Game table, #1611).
`nikaia run benches/game/game.nika -- json` builds both sides, checks that they
print the same bytes and counts them with callgrind.

## The programs

| level | Nikaia | Rust |
|---|---|---|
| the tree | [`tree.nika`](tree.nika): `json::parse` into a `json::Value`, written back with `json::to_string` | [`rust-tree.rs`](rust-tree.rs): `serde_json::Value`, written back with `serde_json::to_string` |
| a type of the program | not built yet: the package's way is `json::read[T]` (ADR-344 D3, ADR-grammar-2 D10), which waits for its build (#604) | `#[derive(Deserialize)]`, with it |

serde_json is built with `preserve_order` (an object keeps its members in the
order of the text, as `json::Value` does), `arbitrary_precision` (a number is
kept as the text it was written as, as `json::Value` keeps it) and
`unbounded_depth` (serde_json stops at 128 levels unless told otherwise; the
package reads 512). Both sides then write back the same text byte for byte:
members in order, numbers as written, no blanks, the escapes RFC 8259 asks for.

## The inputs

Generated by [`input.nika`](input.nika), so every machine counts the same bytes
and no data file is kept here:

| input | bytes | what |
|---|---:|---|
| small | 1,046 | one request body: two records shaped like a social network's message (twitter.json of the nativejson-benchmark), whole numbers, numbers with fraction and exponent, strings with escapes and text outside ASCII, `true`, `false`, `null`, nested objects and arrays, pretty-printed |
| large | 10,000,080 | records as above, and every tenth line 200 coordinate pairs as canada.json holds them |
| deep | 819,202 | 400 chains of objects and arrays in turn, each 511 levels below the top array: the package's limit |

## Where json is behind

json counts 1.4 to 2.0 times serde_json's instructions. From
`callgrind_annotate` of the large input, checks off (2.46 billion against
serde_json's 1.37 billion):

* **The path of every value is built while reading** (30 %; 42 % on deep):
  `value` makes `f"{path}[{at}]"` and `f"{path}.{key}"` for each element and
  member, text only an error ever shows.
* **Text is copied a character at a time** (24 %): `parse` first collects the
  whole input into a list of characters (`text.chars().collect()`, 6 %), and a
  number or string is then built by pushing one character after another
  (`Text::push`, about 30 instructions a call on its own).
